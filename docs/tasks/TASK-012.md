# TASK-012: Colouring modes and CR-002 configuration fields (core)

Spec §5 acceptance: `[unit]` colourScheme modes (distinct repeat after 120, scale by value and by rank, swatch colours, 12 % tint, `mehrere Werte`, `(leer)`), config build/validate/apply for each new field incl. invalid entries, absence defaults (REQ-009-AC5 logic), axis-section conversion both flips (REQ-009-AC4 logic), `sectionPlane` wins over `section`; every invalid case of the DEC-20 field table (logic of REQ-009-AC8); fixtures generated by `scripts/make-config-fixtures.mjs`; updates `test/unit/colouring.test.mjs`, `test/unit/config.test.mjs` and the integration/e2e expectations its change breaks, so the 1.0.0 UI keeps working until TASK-016 and TASK-018; the UI-level ACs are cited in comments only (T5).

## What was built

### cv-core (pure)
- **Colouring (DEC-15 as changed by CR-002)**:
  - `colourScheme(source, key, {mode, colour})` with `mode` `distinct` (default) or `scale`, and `colour` = scale colour `#rrggbb` (either case; default `#d72622`).
  - One entry per distinct non-empty value in value order (`compareValues`, the filter-set order), then `mehrere Werte` (`#6e6259`) and `(leer)` (`#c4c7ca`) in both modes.
  - `distinct`: value number i gets `distinctColour(i)` (golden angle 137.508°, s 0.65, l 0.42/0.58), repeating after 120 values. `repeats` is true with more than 120 values (the note `Mehr als 120 Werte: Farben wiederholen sich.` = `COLOUR_REPEAT_NOTE`).
  - `scale`: numbers by value (t = (v − min)/(max − min), one value t = 1), text or mixed values by rank (t = rank/(n − 1)); `scaleColour(base, t)` = the DEC-15 formula (24 steps, 12 % tint at t = 0). `gradient` = `{from, to, first, last}` for the gradient bar.
  - Entry labels are the table's display text (`displayText`, German numbers).
  - New exports: `COLOUR_MODES`, `SCALE_COLOURS` (Rot, Blau, Grün, Orange, Violett, Grau), `DEFAULT_COLOUR_MODE`, `DEFAULT_SCALE_COLOUR`, `LEGACY_SCALE_COLOUR` (`#1f6fd1`), `COLOUR_LEGEND_LIMIT` (200), `COLOUR_REPEAT_NOTE`, `normaliseHexColour`, `legendRows(legend, limit)` (`{rows, more}` for `+<n> weitere Werte`).
  - Removed: `Sonstige` (`COLOUR_OTHER`, `OTHER_LABEL`) and the numeric ranges (superseded by DEC-15).
- **Configuration (DEC-20 field table)**:
  - `buildConfig` writes `filterRules` (valid rules in order via TASK-011's `normaliseRule`; a `text` rule with key null) and `search` after `filterSets`. In `display` it writes `colourMode`, `scaleColour` (lower case; also while nothing is coloured) and `sectionPlane` (a plane, or a 1.0.0 axis section in the state converted).
  - `buildConfig` never writes `display.section`, nor hidden or isolated elements.
  - `applyConfig` validates and applies every new field:
    - `filterRules`: not a list → `Filterregeln`; a malformed rule → `Filterregel`; a missing key is named; absent → `[]`.
    - `search`: not a string → `Suche`; absent → `""`.
    - `colourMode`: invalid → `Farbmodus`, then treated as absent. Absent → `scale` for a numeric `colourBy`, else `distinct`.
    - `scaleColour`: invalid → `Skalenfarbe`, then treated as absent. Absent → `#1f6fd1` when `colourMode` is absent too, else `#d72622`.
    - `sectionPlane`: invalid → `Schnitt` and the current section is kept. A non-unit normal is normalised without a notice; null → no section. When no model has geometry → `Schnitt`.
    - `display.section` (1.0.0) is read only when `sectionPlane` is absent. A valid one is converted by `planeFromAxisSection` (normal −axis, or +axis when flipped); an invalid one → `Schnitt`. An absent section and an absent plane → null.
  - New exports: `planeFromAxisSection`, `normaliseSectionPlane`, `SECTION_NORMAL_MIN`; `ctx.hasGeometry()` (optional).
- The embedded source stays ASCII-only: the label `Grün` in `SCALE_COLOURS` is written `Grün`. The earlier interrupted run had left a raw `ü` there, which turned the core ASCII tests red.

### Interim wiring so the 1.0.0 UI keeps working (cv-app / cv-ui; replaced by TASK-014/016/018)
- cv-app keeps `colourMode` / `scaleColour` (start `distinct` / `#d72622`), sets them from a loaded configuration and passes them to `colourScheme` and `buildConfig`. It exposes them in `window.__calc.view`.
- `hasGeometry` is passed to `applyConfig`.
- A loaded `sectionPlane` whose normal is ±X / ±Y / ±Z is shown as the equal 1.0.0 axis section (`axisSectionOfPlane`). Any other plane is not applied and is named `Schnitt` (the 1.0.0 3D view cannot cut along it).
- The 1.0.0 legend under the model shows at most 200 rows and then `+<n> weitere Werte`.
- `apply.filterRules` and `apply.search` are validated by the core but not applied by cv-app yet. The app has no rule or search state before TASK-015a/015b; TASK-018 wires them.

## Decisions (for the release gate / orchestrator)
1. **Rank order of text in `Farbskala` is the filter-set value order** (`compareValues`: numbers first, numerically, then text). The reference sorts with `localeCompare("de", {numeric: true})` (ref L501). The colour therefore matches the position in the filter set and the legend (DEC-15 "in value order"). Mixed numbers and text are coloured by rank, as in the reference.
2. **Distinct colours are computed by an own HSL→hex function in cv-core** (no three in the pure core). The unit test checks indices 0..244 against the reference's `THREE.Color.setHSL(…, SRGBColorSpace)`: equal.
3. **A loaded unit normal is kept bit for bit** (within 1e-12 of length 1), and `-0` becomes `0`, so saving a loaded plane gives the same JSON (REQ-009-AC1). Otherwise the normal is normalised.
4. **Interim until TASK-014/018:**
   - A configuration's `sectionPlane` that is not ±X/±Y/±Z is not applied in the 1.0.0 3D view and is named `Schnitt`.
   - Configuration rules and search are validated but not applied, so saving after loading a 1.1.0 file writes `filterRules: []` / `search: ""` until TASK-018. No released build is affected; INC-2 ships as a whole.
5. **The 1.0.0 `Färben nach` control now colours with the DEC-15 start mode `Unterschiedliche Farben`**, also for numeric properties: one colour per value instead of 24 ranges. A configuration without `colourMode` and with a numeric `colourBy` keeps the 1.0.0 look (`Farbskala`, Blau). This is interim until TASK-016's panel offers the modes.
6. `search` is saved and loaded exactly as typed (not trimmed). The filter trims it (TASK-011), so `" wand "` and `"wand"` filter alike but are saved differently.
